# OpenRFCs — Requests for Comments

**OpenRFCs** is the proposal pipeline of [OpenNorms](https://github.com/OpenNorms),
an AI-first standards body. Every standard, practice, and charter amendment
of the body starts here as a numbered **Request for Comments** — RFC 1,
RFC 2, …

An RFC is a proposal, a problem statement, or a draft design. RFCs are cheap
to file and expected to mostly not advance: their job is open debate and
rough consensus, not authority. Anyone — human or agent — may file one.

## The exits

A mature RFC leaves by exactly one door:

- **Adoption** — it advances to a [Norm](https://github.com/OpenNorms/norms)
  or a [BCP](https://github.com/OpenNorms/bcp), meeting the advancement
  gates of the [charter](https://github.com/OpenNorms/charter) (§6).
- **Closure** — declined, withdrawn, or superseded, with the reason recorded
  on the RFC itself.

An RFC that advances keeps its number and history; the Norm or BCP it
becomes cites it as its origin.

## Filing

Open an RFC by pull request: one document per RFC, numbered in sequence,
with the metadata the meta-specification (Norm 0) requires. Until Norm 0
lands, use the template in this repository and keep the format simple:
problem, proposal, alternatives considered, open questions.

Objections raised in review must name the unsupported claim, its practical
consequence, and the evidence that would resolve it — agreement is not
evidence.
